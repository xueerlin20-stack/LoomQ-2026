# LoomQ 干净环境构建与启动

本文说明如何在一台未安装 LoomQ 依赖的机器上构建并启动网页应用。所有命令默认从仓库根目录执行。

## 1. 运行环境

- Git
- Python 3.10
- 可访问所选 OpenAI-compatible 模型服务的网络
- 可选：Docker，用于获得更一致的 Linux 环境

网页前端使用浏览器原生 HTML、CSS 和 ES Modules，不需要安装 Node.js，也没有单独的前端编译步骤。

## 2. 获取代码

```bash
git clone https://github.com/xueerlin20-stack/LoomQ-2026.git
cd LoomQ-2026
```

如果代码已经存在，只需进入仓库根目录。

## 3. 方式一：使用 Python 虚拟环境

### 3.1 创建虚拟环境

推荐把虚拟环境放在 `starter_kit/.venv`。启动器能够自动识别这个位置。

macOS 或 Linux：

```bash
python3.10 -m venv starter_kit/.venv
source starter_kit/.venv/bin/activate
```

Windows PowerShell：

```powershell
py -3.10 -m venv starter_kit/.venv
starter_kit\.venv\Scripts\Activate.ps1
```

确认版本：

```bash
python --version
```

输出应为 Python 3.10.x。

### 3.2 安装依赖

```bash
python -m pip install --upgrade pip
python -m pip install -r starter_kit/requirements.txt
```

### 3.3 配置模型

有两种配置方式，任选其一。

#### 方式 A：通过网页配置

可以暂时不创建配置文件，直接启动网页。首次运行向导会检查并保存以下配置：

- `LOOMQ_LLM_BASE_URL`
- `LOOMQ_LLM_API_KEY`
- `LOOMQ_LLM_MODEL`
- `LOOMQ_LLM_TIMEOUT_SECONDS`

配置只会写入本机的 `starter_kit/.env.l2`，API Key 不会通过配置检查接口回显。

#### 方式 B：提前创建配置文件

```bash
cp starter_kit/.env.l2.example starter_kit/.env.l2
```

编辑 `starter_kit/.env.l2`：

```dotenv
LOOMQ_LLM_BASE_URL=https://api.deepseek.com
LOOMQ_LLM_API_KEY=替换为自己的凭证
LOOMQ_LLM_MODEL=deepseek-v4-flash
LOOMQ_LLM_TIMEOUT_SECONDS=120
LOOMQ_LLM_MAX_OUTPUT_TOKENS=4096
```

不要提交真实的 `.env.l2`。该文件已被 Git 忽略。

可以在调用模型前检查配置：

```bash
python starter_kit/run_l2.py --check
```

检查结果只显示地址、模型和超时等非敏感信息，不显示 API Key。

### 3.4 启动网页

```bash
python starter_kit/web_app.py
```

默认地址：

- 主界面：<http://127.0.0.1:8765/>
- 工作台：<http://127.0.0.1:8765/workspace.html>

启动器默认会打开浏览器。服务器终端应显示：

```text
LoomQ Agent 网页已启动：http://127.0.0.1:8765
按 Ctrl+C 停止。
```

在无图形界面的机器上启动：

```bash
python starter_kit/web_app.py --no-browser
```

自定义监听地址和端口：

```bash
python starter_kit/web_app.py \
  --host 0.0.0.0 \
  --port 8765 \
  --no-browser
```

停止服务时，在启动终端按 `Ctrl+C`。

## 4. 方式二：使用 Docker

Dockerfile 位于 `starter_kit/`，因此构建上下文也应使用该目录。

### 4.1 构建镜像

```bash
docker build -t loomq-agent ./starter_kit
```

需要完全重新安装依赖时：

```bash
docker build --no-cache -t loomq-agent ./starter_kit
```

### 4.2 准备配置

```bash
cp starter_kit/.env.l2.example starter_kit/.env.l2
```

编辑 `.env.l2` 并替换占位 API Key。Docker 的 `--env-file` 会把这些值注入容器，不会把配置文件复制进镜像。

### 4.3 启动容器

```bash
docker run --rm -it \
  --name loomq-agent \
  --env-file starter_kit/.env.l2 \
  -p 8765:8765 \
  loomq-agent \
  python web_app.py --host 0.0.0.0 --port 8765 --no-browser
```

浏览器打开：

```text
http://127.0.0.1:8765/
```

停止容器时按 `Ctrl+C`。如果容器在后台运行，可执行：

```bash
docker stop loomq-agent
```

## 5. 启动检查

检查服务是否可以访问：

```bash
curl http://127.0.0.1:8765/api/config
```

返回 JSON 即表示本地 HTTP 服务已启动。其中 `ready: true` 表示模型配置完整；`ready: false` 时可以回到主界面的“运行配置”完成设置。

建议再完成一次网页冒烟测试：

1. 打开主界面。
2. 确认可以进入新手引导和运行配置。
3. 进入独立工作台。
4. 请求“生成一个 2 比特 Bell 电路并测量”。
5. 继续追问“为什么第一个门是 H 门？”，确认智能体承接当前电路上下文。

## 6. 常见问题

### `python3.10: command not found`

安装 Python 3.10 后重新创建虚拟环境。不要直接使用未经验证的更高版本，因为量子 SDK 的可用 wheel 可能受 Python 版本限制。也可以改用 Docker。

### `ModuleNotFoundError: spinqit` 或其他量子 SDK

确认已经激活 `starter_kit/.venv`，然后重新执行：

```bash
python -m pip install -r starter_kit/requirements.txt
```

### 网页显示“需要完成运行配置”

这是正常的恢复流程。点击主界面的“运行配置”，填写模型地址、API Key、模型名称和超时即可。

### `Address already in use`

端口 8765 已被占用。选择其他端口：

```bash
python starter_kit/web_app.py --port 8877
```

然后访问 <http://127.0.0.1:8877/>。

### 模型请求失败但网页能够打开

依次检查：

1. `LOOMQ_LLM_BASE_URL` 是否为 OpenAI-compatible API 根地址。
2. API Key 是否有效且不是 `placeholder`。
3. 模型名称是否可由该服务访问。
4. 当前机器或容器是否能访问模型服务。
5. 超时是否足够；默认建议 120 秒。

LoomQ 在无法可靠理解模型响应时会如实请求补充信息，不会猜测或编造电路和运行结果。

## 7. 安全提示

- 不要把真实 API Key 写进命令历史、截图、日志或 Git 提交。
- 不要提交 `starter_kit/.env.l2`。
- 对外暴露 `--host 0.0.0.0` 前，应确认所在网络和访问控制是可信的。
- 本地会话当前保存在网页服务进程内存中；重启服务后，多轮对话上下文会被清除。
